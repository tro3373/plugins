## セッションが実際に使った skill とツールにスコープを限る

発見は、このトランスクリプトで呼び出された skill、ツール、MCP を指していなければならない。親が一度も開かなかった skill への推測的なルーティングは数えない。skill が使われたかを確認するには、トランスクリプトから次を走査する:

- 任意の `SKILL.md` ファイルに対する `Read` ツールの呼び出し (ワークスペースの `.cursor/skills/`、ユーザレベルの `~/.cursor/skills/`、または `~/.cursor/plugins/` 配下のプラグイン導入パス)
- skill のパスを名指しする `Task` のプロンプト
- skill が文書化しているコマンドに一致するツール呼び出し (Shell、Grep、MCP など)

妥当な発見の形は 2 つ:

- 親がその skill を呼び出し、あなたがその本文に本物のギャップを見つけた。skill の該当セクションへルーティングする。
- skill はカタログに見えていたが、役立ったはずの場面で発火しなかった。将来のエージェントが拾えるよう skill の description を調整する。`tune description: <skill path>` としてルーティングする。

呼び出されてもおらず、発火漏れの候補でもない skill は落とす。

見つけた永続的な学びをすべて挙げる。それぞれについて:
- Principle: 何が一般化するかを 1 文で述べる。ラベルではなく規則を述べ、名前を出すだけで済ませない。
- Evidence: それを浮かび上がらせたトランスクリプト上の正確な瞬間 (ターン番号または短い引用)。
- Routing: 最も関連する既存の skill (トランスクリプトに現れるとおりの `SKILL.md` パスを示す)、または skill が発火すべきだったのにしなかった場合は `tune description: <skill path>`、既存のどの skill も本来の置き場でないなら "new skill: <kebab-name>"。

些末なもの (タイポ、ツールのリトライ、機械的なセットアップ) は飛ばす。親が従った既存の skill からすでに明らかなものは飛ばす。ドリフトする実装詳細 (特定の SHA、現在のファイルパス、バージョン番号、正確なバイト数) は飛ばす。コードのドリフトを生き延びる原則とパターンだけを挙げる。
