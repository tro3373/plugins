# Subtract Before You Add

システムを進化させるときは、まず複雑さを取り除き、それから作る。

**なぜ:** 複雑なシステムへの追加は複雑さを複利で増やす。先に取り除くとコードが減り、本質的な構造が現れ、たいてい次の設計が自明になる。既定は引き算だ。

単純化を継続的な投資にする。見つけたときより設計をわずかに単純にし、同じかより小さい表面でより多くのことができるようにして去る。

**パターン:**
- 構築より先に削除を並べる
- 磨く前に削る (品質に投資する前に最小まで持っていく)
- 観察された使われ方に合わせて設計し、思弁的なエッジケースに合わせない
- 仕様が要求する以上の、思弁的なバリデータ、パーサ、ガードを作らない
- プロンプトを単純化する (冗長な指示、過剰なテンプレートを削る)
- リファレンスに目新しい内容が無いなら、スタブを残さず削除する
