### skill を書く / 変更する

**skill の声はあなたの担当。**

1. **create-skill** skill (SKILL.md ファイルを書くための Cursor 組み込みのもの) を使う。
2. skill を検証する: frontmatter に `name` と `description` があること、参照するファイルが存在すること、skill 間のリンクが解決すること。
3. 構造的なものならテストケースを書く。主観的なものなら省く。
4. **PR を開く** を実行する。

迷ったら削除する。判断を変える文章だけを残す。やるべきことを言い、理由は省く。理由が無いと規則が分かりにくいときだけ説明する。トーンはスコープに合わせる。構造的な出所 (型、README、設定) を **encode-lessons-in-structure** の原則 skill に従って指し示す。他の skill へはパスで委譲する。言い直してはならない。何度もぶつかるのに捕捉されていないワークフローがあれば => 新しい skill を提案する。

**返答:** skill の要約、主要な設計判断、検証のメモ。
