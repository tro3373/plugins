### Autopilot-stack

**あなたが所有するのはスタックであって、着地ではない。オペレータがレビューして着地させる、ベースで連結された PR の 1 本の線形なスタックを渡す。** **Autopilot-full** は、検証済みの作業の出口を除いてそのまま成り立つ。各ティックは両方のプレイブックを trunk から読み直し、食い違う箇所ではこちらが優先する。

1. **Autopilot-full のオーナーを、着地を除いて走らせる。** オーナーは merge-ready の代わりに STACK-READY を報告する。他のブランチ (trunk を含む) への rebase は決して行わず、再ターゲット、マージ、PR のクローズ、auto-merge の仕込みも決して行わない。チェーンのトポロジは root が持ち、着地はオペレータが持つからだ。ある項目が別の項目に依存するとき、そのオーナーは trunk ではなく、その項目のブランチから分岐する。
2. **トポロジの書き手は 1 人にする。** オーナーは自分のブランチだけを push し、各 tip と意図する親を報告する。リンクを rebase または再ターゲットするのはあなただけだ。1 本のチェーンに書き手が 2 人いると互いの作業を打ち消すからだ。クリーンな PR は依存順に追記し、そのベースを親のブランチに設定する (`origin pr edit <pr> --base <parent-branch>` か `gh pr edit <pr> --base <parent-branch>`)。`gt` を必須にしてはならない。オーナーはあなたの push を新しいベースとリースとして受け取り、競合したら自分の担当分を解決して、あなたが push する。
3. **ドリフトは root で吸収する。** 着地が始まるまでは、各リンクに Autopilot-full ステップ 5 のテストを当て、必要とされるところでチェーンを下から上へ rebase する。そのうえでリンクごとに patch-id ルールを適用する。リンクのベースはその親だからだ。
4. **チェーンを配送し、その後は手を出さない。** 各リンクは PR に自分の評決を持つ。着地が始まったら、`playbooks/shipping.md` が認めるマージ後の再ターゲットを除き、誰もチェーンに書き込まない。2 人目の書き手が進行中の着地を壊すからだ。着地中の問題はあなたを通じてオペレータへ上げ、修正はオペレータの go を待つ。

**どちらの autopilot を選ぶか。** PR が独立していて着地の権限が与えられているなら Autopilot-full。オペレータが着地前のレビューを望むとき、作業が順序付けられているか結合しているとき、あるいはマージ権限が与えられていないなら Autopilot-stack。

**返答:** **ketchup** skill に従ってオペレータに追いつかせる。スタックの root と tip へのリンク、リンクごとの 1 行の評決、そして保留または除外したものとその理由を含める。
