### Autonomous run

**終了条件はあなたの担当だ。done を定義し、止まらずにそこまで走らせる。**

1. 最初のイテレーションの前に、終了条件をチェック可能な述語として述べる (テストが green、repro が解消、N 本の PR がすべて merge 済み、pixel-diff がゼロ)。
2. Cursor の `/loop` コマンド (pstack skill ではなく組み込み) を使って wake 機構を選ぶ。監視対象のイベント (CI、merge、ref の前進) がある場合は、そのイベントで起こす watcher サブエージェントを付け、長めの時間ベースの heartbeat をフォールバックにする。イベントが無い場合は、結果を再確認する価値が出るタイミングに合わせた固定間隔の heartbeat を使う。
3. 各イテレーションは証拠が正当化する最小の変更を行い、述語に対して検証し、前進したならコミットし、役に立たなかった変更は破棄する。「役に立つかもしれない」程度の念のための対策は revert する。放置しない。
   **sequence-verifiable-units** の principle skill に沿って作業を順序付け、チェックを最後にまとめるのではなく各ユニットを次に進む前に検証する。
4. 実行中に見つけたものはあなたの担当だ。壊れた skill、関連するバグ、不安定な verifier、レビューのノイズ、ツールの失敗、放置されたフォローアップ、直せる drift は poteto-mode 経由で自分で対処する。本題外の修正は独立した PR に入れる。可逆な作業を人間のために保留したり、`AskQuestion` を使ったりしない。表に出すのは、不可逆な操作、実験では決着しない本物のプロダクト判断・好みの判断、あるいは本物の行き止まりだけだ。述語を主たる駆動力として保ち、脇の修正が終わるたびにそこへ戻る。
5. **show-me-your-work** skill を通じてイテレーションごとにチェックポイントを取り、何が変わったか、述語が動いたかを 1 行記録する。
6. 述語が満たされたら止まる。プラトーは停止理由ではない。走り続け、突破するためにアプローチを転換する。空回りするくらいなら本物の行き止まりとして表に出す。勝利宣言のために述語を緩めては絶対にならない。

**返答:** 終了条件、実行したイテレーション数、着地したもの、破棄したもの、最終的な述語の状態。
