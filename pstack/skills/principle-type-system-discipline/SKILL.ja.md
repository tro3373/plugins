# Type System Discipline

コンパイラに、ありえない状態、噛み合わないプリミティブ、扱われていないバリアントを拒否させる。ハンドラを増やすより、エラーと特殊ケースを存在ごと定義から消すことを優先する。TypeScript の構文は `typescript-best-practices` skill を見よ。

- **不正な状態を表現不能にする。** バリアントは、矛盾する組み合わせがコンパイルを通ってしまう省略可能フィールドの寄せ集めではなく、直和型 (判別可能な union、ペイロード付きの enum、sealed class) でモデル化する。`{ completed: boolean; completedAt?: Date }` は、日付の無い `completed: true` を許す。boolean を `completedAt` から導出するか、`{ kind: 'open' } | { kind: 'done'; at: Date }` とモデル化する。フィールドの組み合わせがいつ有効かを説明するコメントが書けるなら、直和型に分割する。
- **型は制限ではなく構成である。** 緩い型からチェックで切り出すのではなく、欲しい値から型を組み上げる。空でないリストは先頭と残りである。有効な時間範囲は開始と期間である。不正な値を作れない形を選び、その上に呼び出し元が必要とするインターフェースを公開する。
- **意味を持つプリミティブをブランド化する。** `UserId` と `OrderId` は中身は文字列だが、互換にしてはならない。それぞれに独自の型を与える (TypeScript ならブランド付き交差型、他の言語なら newtype)。作成時に一度だけ検証し、以降は型を信頼する。2 つの引数が同じプリミティブ型で意味が違うなら、ブランド化する。
- **外部データはパースされるまで型が無い。** RPC ペイロード、JSON、IPC メッセージ、CLI 引数、設定ファイル、環境変数、データベースの行。あらゆる境界に、構造化されていない入力を型付きモデルに変えるパース関数を置く。バリデーションをどこに置くかは **boundary-discipline** principle skill が述べる。
- **型システムに嘘をつかない。** キャスト、安全でない型強制、コンパイラを迂回するアサーション関数は、潜在的なランタイムクラッシュである。コンパイラが事実を証明できないなら、自分で証明する (検証する、絞り込む、モデルを洗練する)。さもなくば、そのキャストが危険物だと認める。`any`、`as`、`assertNotNull` のそれぞれを境界まで辿り、そこで検証する。
- **網羅的マッチはコンパイラの仕事である。** 直和型へのマッチは、新しいバリアントが扱われずに追加されたらコンパイルが失敗しなければならない。そうすれば、次のエージェントはコンパイラからケースを足す場所を教わる。その言語の定石を使う。TypeScript では `never` 型の束縛、Rust では注釈なしの `match`、Haskell では `-Wincomplete-patterns`、Kotlin では sealed class の match の網羅性。
- **正典のスキーマから型を導出する。** protocol buffer、OpenAPI 仕様、GraphQL スキーマ、データベースのマイグレーション、デザイントークンのファイル、あるいは他のファイルが形を所有しているなら、並行する型を手で書く代わりにそこから導出する。**encode-lessons-in-structure** principle skill を見よ。
- **部分性が現れる場所でだけ型を強くする。** ランタイムのアサーション、null チェック、「ここには来ないはず」という throw は、型が弱すぎる場所の目印である。そのチェックを型へ押し上げる。そして止まる。型システムの仕事は、各利用箇所が扱わねばならないケースを追跡することであり、データをできる限り正確に記述することではない。全域関数を優先する。空リストの `sum` は 0 なので、普通のリストを取る。空リストの `head` には答えが無いので、空でないリストを要求する。そうしなければ panic するものが無いなら、普通の型のままにする。
