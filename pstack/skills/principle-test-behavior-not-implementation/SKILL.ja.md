# Test Behavior, Not Implementation

テストはコードをそのユーザーと同じ呼び方で呼び、観測される結果をリテラルな期待値に対してアサートする。コードがどの呼び出しをしたかをアサートする、あるいはコードが持つ定数を言い換えるだけのテストは、そのどちらもしていない。

チェック方法: テストを残す前に、インポートした全ての関数が `undefined` を返してもそのテストが通るかを問う。通るなら、それは何の挙動も観測しておらず、欠陥があっても失敗できない。アサーションを書き直すか、テストを削除する。

**なぜ:** 欠陥があっても失敗できないテストは CI の時間とレビューの注意を消費し、何も捕まえない。定数を固定するテストは、誰かがその定数やそれを言い換えたプロンプトを編集したときにも失敗するため、その編集を妨げる。

**インポートした全ての関数が `undefined` を返しても通る 5 つの形:**

- **アサーションが弱い、またはない。** `expect` がない、あるいは `toBeDefined`、`toBeTruthy`、`not.toThrow`、`toBeInstanceOf`、`toBeGreaterThan(0)` だけ。
- **モックか不在だけ。** `toHaveBeenCalled`、`not.toHaveBeenCalled`、`toBeUndefined`、`toEqual([])`、`toHaveLength(0)`、`not.toBe(wrongValue)` だけ。
- **自己参照。** 期待値がテスト対象のコードから来ている: `expect(f(a)).toBe(f(a))`、`expect(parsed.url).toBe(buildUrl(...))`。
- **定数の固定。** アサーションが、手で保守された定数、設定のデフォルト値、テーブルの行、プロンプト文字列を言い換えているだけ: `expect(LIMITS.maxTools).toBe(8)`、`expect(PROMPT).toContain("You are")`。
- **フィクスチャがフィクスチャをアサートする。** アサーションがテストが構築したデータや `beforeEach` で計算した値を読み、対象がテスト本体の中で一度も実行されない。

**直し方:** テスト本体の中で対象を 1 つの具体的な入力で呼び、リテラルな出力または観測可能な効果をアサートする。`expect(slugify("Hello, World!")).toBe("hello-world")`。不在をアサートするなら、同じテストの中で別の入力に対する存在をアサートする。定数については、その値を言い換える代わりに、それを読む機構を 1 つの入力でテストする。モックについては、呼ばれたことではなく、それが受け取ったペイロードや呼び出し後の状態をアサートする。そのようなアサーションが存在しないなら、テストを削除する。

**残す:** テーブルの行をまたぐ関係のテスト (2 つのテーブルに存在するキー、存在する親) と、`*.test-d.ts` ファイル内のコンパイル時チェックは残す。
