# Figure it out

タスクにマッチするプレイブックがないなら、設計せよ。コードを書く前の成果物はワークフローそのものである。すなわち、タスクに応じて厳密さをスケールし、科学的方法を回し、人間が席を外した後に監査できる決定の軌跡を残す、フェーズの列である。

## 開始

todolist を開き、その最初の項目を **poteto-mode** skill の Principles セクションを読むことにする。次に、以下のフェーズを todo として追加する。

## Phase A: フレーム

まず地固め、それから確約。次を述べられるようになるまで実行を始めてはならない:

- 反証可能な述語としての完了の定義 (**prove-it-works** の原則 skill)。
- 定量化されたスコープ。おおよそのユニット数と労力、加えて地固めで浮かんだブロッカー。
- 厳密さのレベル。高い方に倒す。一方通行の扉と影響範囲の大きいものは厳密さを増やし、可逆で低リスクなステップは減らす。厳密さとはゲートとアーティファクトのことであって、「もっと頑張る」ことではない。

長い実行に確約する前に、フレームとトレードオフを提示する。可逆な作業は進める (**never-block-on-the-human** の原則 skill) が、数時間かかる実行はチェックポイント 1 回に値する。

## Phase B: ワークフローを設計する

原子的で独立に着地可能なユニットへ分解する。最もリスクの高い未知から順に並べる。足場と検証は機能より先に来る (**foundational-thinking** の原則 skill)。

- 作業の前に検証ハーネスを作り、変更前の状態からベースラインを取る。チェックが「旧の値 vs 新の値」として読めるようにするためである。
- 一方通行の扉となる設計判断には **architect** skill を回す (これが **arena** を回す)。形が既に具体化している機械的な作業では飛ばす。決着済みの設計に対する 2 度目の arena は過剰設計である (**laziness-protocol** の原則 skill)。
- 何を fan-out するかを決める。並列化は継ぎ目に沿ってのみ行い、各ワーカーに自分の worktree かブランチを与える (**separate-before-serializing-shared-state** の原則 skill)。fan-out しすぎない。
- 設計したフェーズのリストを書き出す。人間がレビューするのはそのリストである。

そして設計を実行する。その手順を具体的な項目として todolist へ追加する。位置は Phase C のエントリの後、Phase D の前。各手順は Phase C のループ規律の下で走らせ、Phase D のログはそれらの間に織り込む。軌跡全部を最後まで取っておくのではなく、1 手順が着地するごとに 1 行を書く。

## Phase C: ループを回す

各ユニットは実験である。仮説を述べ、最小の変更を加え、実アーティファクト上で述語に対して測定し、前進したなら残し、そうでなければ戻す。
**sequence-verifiable-units** の原則 skill を適用し、チェックを最後にまとめるのではなく、次を始める前に各ユニットを検証する。

- 自己申告ではなく、アーティファクトを検査して検証する。あまりに簡単に通ったときは、システムより先に観測方法を疑え。
- 委譲した作業にはジャッジを組ませる。ワーカーがゲートをすり抜けるようなら、リセットして契約を固くする。ゲート自体が間違っているなら、迂回するのではなくゲートを独立した変更として直す。
- 評決は VERIFIED、NOT VERIFIED、INCONCLUSIVE のいずれかである。Inconclusive は合格ではない。ネガティブな結果を隠すな。

## Phase D: 監査の軌跡を残す

実行のログは **show-me-your-work** skill 経由で取る。figure-it-out の作業はたいてい、レビュワーが PR で読めるように軌跡をコミットするだけの野心を持っている。軌跡と差分の組が、人間が戻ってきてその作業を信頼できるようにする。

## Phase E: 検証して引き渡す

ハーネスだけでなく実プロダクト上で、全体を Phase A の述語に照らして確認する。繰り返し発生した修正はゲート、lint ルール、チェック、スクリプトとして符号化する (**encode-lessons-in-structure** の原則 skill)。

**返答:** 設計したプレイブック、厳密さのレベルとその理由、決定の軌跡のパス、述語に対して検証済みのもの、そしてまだ未解決のもの。
