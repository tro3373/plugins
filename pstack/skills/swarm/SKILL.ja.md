# Swarm

N 体の並列クラウドワーカーにファンアウトする。それぞれ別のスライスを担当してもよいし、同一のブリーフでレースしてもよいし、両方を混ぜてもよい。親は待ち、集約し、1 つのレポートを返す。

## 開始

何かを起動する前に、フェーズごとに 1 エントリの todolist を開く。

1. Frame
2. Fan out
3. Aggregate
4. Report

## Phase A: Frame

1. done の述語と、swarm が返さねばならない成果物またはレポートを述べる。
2. 形を選ぶ。スライスに分割するか、N 体のワーカーを同一ブリーフでレースさせるか、両方を混ぜるか。レースまたは混合の形なら、起動前に `first pass`、`rank all`、`best-of` のいずれかを宣言する。
3. N はユーザから決めるか、形から導く。N はワーカーの総数であって、クラウドの同時実行上限ではない。
4. ワーカーのモデルは、`~/.cursor/rules/pstack-models.mdc` の `swarm workers` 行から選ぶ。ルールまたはその行が無ければ `grok-4.7-xhigh-fast` を使う。`auto` または `inherit-parent` なら、`model` を省略してワーカーを親のモデルで動かす。Task ツールが slug を拒否したら、既定値を使ってその旨を述べる。既定値も拒否されたら、そのエラーメッセージにある同じファミリの最も近い有効な slug を使う。モデルレースの場合は、各アームのモデルを先に名指しする。
5. ワーカーが書き込みを行うなら、それぞれに自分専用の書き込み可能な出力先を与える。ワーカーがコミットを検証または計測するときは、各ブリーフに対象の正確な SHA を名指しする。計測のブリーフには手法 (サンプル数、1 サンプルが何か、順序) も名指しする。ワーカーはその結果に両方を記録する。

## Phase B: Fan out

N 体のワーカーすべてを 1 メッセージで、`subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`、およびステップ 4 のモデル (`auto` または `inherit-parent` なら未設定のまま) で起動する。`environment: "local"` は、ワーカーがユーザのコンピュータ上の何かにアクセスする必要があるときだけ使う。

ワーカーが既定でないプッシュ済みブランチから始めなければならないときは、`cloud_base_branch` を渡す。

どのブリーフも単独で成立させる。ゴール、スコープ、正確なスライスまたはレースのアーム、検証方法、報告内容を含める。レポートは `PASS`、`ISSUES`、`BLOCKED` のいずれかを証拠付きで使う。欠陥を証明できるワーカーは `ISSUES` を報告し、最初の 1 件だけでなく証明できるすべての issue を列挙する。

ワーカーが脱落したら、N-1 で進め、そのことを記す。

## Phase C: Aggregate

終端の結果を読む。ブリーフが名指しした SHA と手法を記録していない結果は破棄し、そのワーカーを 1 回だけ再実行する。2 回目も外したら、欠落として記録する。欠落は合格として数えない。カバレッジなら、必須のスライスすべてに結果が要る。レースなら、先に宣言した選択ルールを適用する。first pass、rank all、best-of を使う。ワーカーの生ダンプを貼り付けない。

コンパクトな結果表、証拠付きの 1 行 issue、そして明示的な欠落や脱落を保つ。

## Phase D: Report

表、issue の 1 行要約、欠落や脱落、そして使ったならレースのルールを含む、統合された 1 つのレポートをチャット内で返す。
