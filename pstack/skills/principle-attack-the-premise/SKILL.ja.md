# Attack the Premise

1 つの前提を共有する 2 つ以上の修正が同じゲートに落ちたら、修正ではなく前提を疑う。

**なぜ:** 失敗した修正は、それぞれが仮定していた信念に不利な証拠である。同じ前提に立つ 3 つ目の修正は、証拠が既に原因ではないと示している場所に労力を使う。

**パターン:**
- **前提を書き出す。** 前提とは、失敗した全ての修正が仮定していた 1 文である。
- **次の修正の前に前提を検証する。** 前提が偽なら結果が変わるはずの観測を見つけ、それを取る。失敗の大きさだけでなく、その分布を見る。検証は [Build the Lever](../principle-build-the-lever/SKILL.md) に従い、再実行可能にする。
- **証拠に従う。** 証拠が前提と矛盾するなら、原因は別にある。前提が予測しなかった、失敗に共通するものを探す。証拠が前提を裏付けるなら、[Fix Root Causes](../principle-fix-root-causes/SKILL.md) に従い次の「なぜ」を問う。以前の修正は、原因ではなく結果を処置していた可能性がある。
- **条件を補うのではなく取り除く。** [Laziness Protocol](../principle-laziness-protocol/SKILL.md) に従う。ある部分が常に負け側に回ることを証拠が示すなら、そこへ追いやっているものを変える。後始末をする仕組みは、原因をそのままにして毎回の作業を増やす。

**止まる:** 前提を書き出して検証するまで、次の修正に着手しない。

この原則は [Redesign from First Principles](../principle-redesign-from-first-principles/SKILL.md) とは別物である。あちらは新しい要件を中心に設計を作り直す。こちらは現在の設計が仮定している事実そのものを疑う。
