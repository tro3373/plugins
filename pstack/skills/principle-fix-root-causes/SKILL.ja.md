# Fix Root Causes

デバッグでは症状を直すのではない。全ての問題を根本原因まで辿り、そこで直す。

**なぜ:** 症状への対処は積み上がる。回避策のたびにシステムは理解しづらくなり、本当のバグは残ったままである。根本原因の修正は前倒しでは時間がかかるが、デバッグの総時間を減らす。

**パターン:**
- まず再現する
- 根本原因に当たるまで「なぜ」を問う
- ガードを足さない (クラッシュを黙らせるための nil チェック追加は症状への対処である)
- 回避策の正当化に段落 1 つ分のコメントが要るなら、そのコードが間違っている (コメントではなくコードを直す)
- インスタンスだけでなくパターンを確認する (同じパターンを grep し、全てのインスタンスを直す)
- 詰まったら計測する。推測しない (ログを足し、実際のエラーを読む)

**再起動で出るバグ: コードより先に状態を疑え**

「再起動後に失敗する」ものは、まず古い永続状態を疑う - 設定ファイル、キャッシュ、ロックファイル、シリアライズされた状態。状態ファイルを消して挙動が戻るなら、状態のバリデーションを修正として優先する。
