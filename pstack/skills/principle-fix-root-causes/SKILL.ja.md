# Fix Root Causes

デバッグでは、現れた場所ではなく欠陥そのものを直す。症状とは、誤った状態が見えるようになった場所である。根本原因とは、システムがすべきでないことをした、または扱うべき状態を扱えなかった最初の場所である。

**なぜ:** 症状への対処は証拠を隠し、欠陥を別の場所で現れるままにする。そのたびにシステムは理解しづらくなる。コードが、誰も名指ししていないバグへの回避策を抱えることになるからだ。

**パターン:**
- まず再現する。
- 答えが、先行する決定の結果ではなくコード内の誤った決定になるまで、各段で「なぜ」を問う。
- 詰まったら計測する。実際のエラーと実際の状態を読む。推測しない。
- 症状を引き起こした状態が正当かを問う。システムがその状態になりうるなら、それで壊れたコードが根本原因であり、そこでその状態を扱うのが修正である。その状態が存在すべきでないなら、壊れた場所に置くチェックはバグを隠す。その状態を作ったものを見つける。ガード、リトライ、握りつぶしたエラー、クランプした値、捨てた状態は、バグを隠す典型的なやり方である。
- 再起動後にだけ失敗するときは、まず永続状態を疑う。設定ファイル、キャッシュ、ロックファイル、シリアライズされた状態。
- インスタンスだけでなくパターンを確認する。同じ欠陥のある箇所を全て見つけ、全て直す。
- 回避策の正当化に段落 1 つ分のコメントが要るなら、そのコードが間違っている。コメントではなくコードを直す。
- 決め手の事実を見つけるのに深い調査が要ったなら、最初の一瞥で見えたはずの、安価で常時有効なシグナルを提案する。
