# Outcome-Oriented Execution

滑らかな中間状態を保つことよりも、意図された検証可能な最終状態を最適化する。

**なぜ:** 全ての中間ステップを完全に安定させ続けると、多くの場合、長生きする負債になる一時的な互換コードが生まれる。ターゲットのアーキテクチャに収束させ、明示的な検証境界で正しさを証明する。

**コアルール:**
- 遷移中の安定性より最終状態の整合性を優先する
- 中間の破壊は、計画され、スコープが切られ、可逆であるなら許容される

**ガードレール:**
- 明示的なフェーズ境界を持つ、計画された書き直しとマイグレーションでこれを使う
- 一時的な破壊が許容される箇所を宣言する
- マイグレーション中も、実際に触っている領域についてはシグナルの高いチェックを維持する
- プラン完了時には静的検証とランタイム検証の両方を完全に要求する
