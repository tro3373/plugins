# Epistemics

証拠が過去のものであり、断片的で、時に矛盾するとき、確信度をどう扱うか。そしてそれを偽の確実性に潰さずにどう伝えるか。

コードは自らの動機を運ばない。コードが何をするかは読める。だが*なぜそれが存在するか*は読めない。それはコミット、PR、チケット、ドキュメント、会話の中にある - どれも不完全で、偏っており、まるごと存在しないこともある。そうでないふりをすると、自信ありげに聞こえる推測が生まれ、ユーザを誤らせる。

## 確信度のティア

最終出力の全ての主張は、以下のいずれかのティアに属さねばならない。ティアが、その主張をどの出力セクションに置くか、どう言い回すかを決める。

### 1. Direct

問いに答える明示的なテキストの引用。「コードが X をしているのだから作者は X を望んだに違いない」ではない。作者が実際に*書いた*、理由を述べる何かである。

例:
- 「1000 件を超えるアイテムを持つユーザがページングできないバグを修正する」と書かれた PR の説明
- 「顧客 Acme がセキュリティレビューで要求したので追加する」と書かれたチケット
- 「// upstream の API がこれより大きい値を拒否するので 100 に clamp する」というコードコメント
- 「再起動をまたいだ永続化が必要なので、選択肢 B ではなく A を選んだ」と書かれた設計ドキュメント
- 「古いやり方はテストで不安定だったのでこのアプローチに切り替える」という作者のチャットメッセージ

言い回し: 断定的、現在形。「これは X のために存在する」。ソースを引用する。

### 2. Supported

複数の間接的な証拠が収束している。単一のソースが明示的に述べてはいないが、ソース横断のパターンからそれが確からしい。

例:
- PR のタイトルが「improve performance」、チケットのラベルが「perf」、周辺のコミットが全て同じホットパスを触っている
- 変更と一緒にテストが複数追加され、いずれも非常に大きな入力のエッジケースを突いている
- 同じ週の作者の他の PR が、説明で全て同じインシデントに言及している

言い回し: 断定的だが、導出されたものだと明らかにする。「証拠は X を強く示している: [具体的な各要素]」。複数のソースを引用する。

### 3. Inferred

文脈の合理的な読みではあるが、明示的に裏付けるものはない。読み手は、これが記録上の事実ではなく*あなたの解釈*だと理解できねばならない。

例:
- PR には理由が書かれていないが、(インシデントチャンネルのタイムラインから) 本番でエラーが起きており、修正が急いで入れられた (同日マージ) ことを踏まえると、hotfix だった可能性が高い。
- 関数名はリトライロジックを示唆し、リトライ回数は 3 で、これはコードベースの他の場所に見られるチームの一般的な慣行「3 回リトライ」と一致する。

言い回し: ヘッジする。「〜のように見える」「おそらく」「〜を示唆する」「〜と整合する」「ひとつの読み方としては」。推論の連鎖を明示する: 「A と B を踏まえると、D の理由により C が有力に見える」。

### 4. Speculative

もっともらしい仮説だが、証拠は薄く、他の説明も同程度に当てはまる。これを提示することには価値があるが、推測だと明確に印を付ける。

例:
- 「これは既に修正済みのブラウザのバグへの回避策かもしれないが、当時の証拠は見つからなかった。」
- 「この閾値は SLA のコミットメントに合わせて選ばれた可能性があるが、それを参照する SLA ドキュメントはない。」

言い回し: 明示的に推測として。「ひとつの可能性は X だが、直接の証拠はない」。通常は「Competing Hypotheses」セクションに、他の可能性と並べて置く。

### 5. Unknown

探したが分からなかった。妥当かつ重要な結果である。記録せよ。

言い回し: 「X、Y、Z を探したが、理由を示す証拠は見つからなかった」。*何を*探したかを具体的に述べる。「分からなかった」は「チケットトラッカーをキーワード A と B で検索し、2023 年以降にこのファイルを触った 6 件の PR を精査し、閾値と一致する文字列リテラルをリポジトリ全体で grep したが、いずれからも設計判断の根拠は出てこなかった」より有用度が低い。

## 言い回しガイド

### 確信を帯びる語。慎重に使う

これらは **Direct** または **Supported** の確信度を含意する。推論に使ってはならない。

- 「because」。証拠を伴う因果の主張を含意する
- 「the reason is」。同上
- 「was designed to」。作者の意図を主張する
- 「fixes」「addresses」「solves」。その変更が目的を達成したと主張する
- 「the team decided」。集団の決定があったと主張する

これらを使うなら、すぐ隣に引用がなければならない。

### ヘッジする語。推論に使う

- 「appears to」
- 「seems to」
- 「likely」
- 「suggests」
- 「is consistent with」
- 「one reading is」
- 「plausibly」
- 「may have been」
- 「the evidence points toward」

これらは、報告ではなく解釈をしていることを示す。「What We Can Reasonably Infer」セクションでは惜しまず使う。

### 避けるべき語

- 「obviously」。自明ならユーザは尋ねていない
- 「clearly」。ほぼ必ず、明らかでない主張の直前に来る
- 「of course」。同上
- 「just」(「it's just X for performance」のような)。切り捨てるような語で、たいてい不確実性を隠している
- 「I think」「I believe」。あなたは証拠を統合しているのであって、個人的な意見を述べているのではない。代わりに「the evidence suggests」を使う

### 合理化を避ける

今日「筋が通って見える」コードも、今はもう当てはまらない理由で、あるいは書かれた当時から間違っていた理由で書かれたのかもしれない。散らかった歴史に、後からきれいな根拠を貼り付けてはならない。

次の衝動に抗え:
- 作者は「正しい」ことをしたと仮定し、そこから逆算して正当化する
- コードベース全体で一貫したパターンは意図的だったと仮定する - 実際はコピペかもしれない
- 証拠の不在を、不在の証拠に変える (「誰もセキュリティの懸念に触れていないのだから、懸念ではなかったに違いない」)

## The Sycophancy Trap

ユーザは `why` の問いに仮説を埋め込んで尋ねることが多い: 「なぜこのやり方をしているのか、パフォーマンスのためだと思うのだが?」。単に肯定してはならない。それを候補のひとつとして扱い、証拠を独立に確認する。証拠が支持するなら引用付きでそう言う。そうでないならそう言い、証拠が*実際に*支持するものを提示する。

ユーザの推測は、調査のきっかけであって、検証して承認すべき結論ではない。

## 証拠が矛盾するとき

2 つのソースが食い違う (PR の説明とチケットの内容が違う) なら、両方を提示する。きれいな筋書きに合う方を選んではならない。典型的なパターン:

- **チケットには** 「顧客 X のコンプライアンス要件のためにこれが必要」とある
- **PR には** 「この領域の技術的負債の整理」とある

両方が真かもしれない (チケットが作業の動機で、PR は作者によるその位置付け) し、片方が誤りかもしれない。両方を引用付きで提示し、判断はユーザに委ねる。

## 証拠が欠けているとき

正直な「分からない」は、この skill が生み出しうる最も価値ある出力のひとつである。ユーザはこれで次を知る:

- 答えは分かりやすい場所にはない
- 知るには人間 (元の作者、プロダクトオーナー、チームリード) に聞く必要がある
- あるいは、その問いはこれ以上追う価値がないと判断できる

ギャップに印を付けず、自信ありげな推測で埋めることは、ユーザに実害を与える。ユーザはその推測に基づいて動く。

ギャップに行き当たったら、具体的に名指しする:
- 答えようとしていた問いは何か
- どのソースを探したか
- それぞれで何を検索したか
- 何が見つかったか (何もなかった、あるいは間接的に関係する材料だけ)

## 確定前のキャリブレーションチェック

出力を渡す前に、synthesizer は「What We Found」と「What We Can Reasonably Infer」の全ての主張を見直し、次を問う:

1. この主張に引用はあるか? ないなら、引用を足すか「Inferred」/「Hypotheses」へ移す。
2. 言い回しはティアに合わせて調整されているか? (Direct な主張は「because」を使ってよい。Inferred な主張は使えない。)
3. コード自身を、それ自身の意図の証拠として扱っていないか? そうなら、それは証拠ではない。削除するか分類し直す。
4. 出力に「What We Don't Know」セクションはあるか? ギャップが 1 つも挙がっていないなら疑わしい。証拠が異例なほど完全だったか、何かを絨毯の下に掃き込んでいるかのどちらかである。
