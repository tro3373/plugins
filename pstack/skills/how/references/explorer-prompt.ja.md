## 探索の指示

まず関連するコードを見つけることから始める。Glob でディレクトリとファイルを探し、Grep で主要なシンボルを探し、Read で実際の実装を理解する。名前から推測するな。コードを読め。

次のパターンに従うこと。
1. **エントリポイントを見つける。** この振る舞いを引き起こすのは何か。ユーザの操作か、API 呼び出しか、スケジュールされたジョブか。どこで始まるかを突き止める。
2. **フローを辿る。** エントリポイントからコールチェーンを追う。各関数を読む。どんなデータが流れ、どう変換されるかを理解する。
3. **主要な抽象をマップする。** どの型・インターフェース・サービス・クラスが中心にあるか。それらの定義を読む。何を表しており、なぜ存在するのかを理解する。
4. **境界を見つける。** このサブシステムはどこで他とインターフェースするか。何が入り、何が出ていくか。
5. **非自明なものを探す。** 意外なところはないか。歴史的な遺物に見えるものはないか。新入りが誤解しそうなところはないか。

手を振って誤魔化さずに全体像を語れるようになるまで探索を続ける。辿れない部分にぶつかったら、そう明言する。「X が Y にどう繋がるか判断できなかった」の方が、でっち上げるよりましだ。

## 出力

発見はこの構造で返す。事実に即し、具体的に書く。関連する箇所では正確なファイルパス、関数名、型名、行番号を参照すること。

### Components Found
主要な型・サービス・クラス・抽象。それぞれについて、名前、ファイルパス、何をするかの一文の説明。

### Flow
実行フローをステップごとに。各ステップについて、どの関数 / メソッドが走り、どのファイルにあり、何をし、次に何を呼ぶか。ステップ間を流れるデータも含める。

### Files Read
探索中に読んだすべてのファイル。説明を書くエージェントが参照できるようにするため。

### Boundaries
このサブシステムがコードベースの他の部分と繋がる場所。入力と出力。

### Non-Obvious Things
意外なもの、歴史的な経緯によるもの、間違えやすいもの。ある動き方をするように見えて別の動き方をするもの。

### Open Questions
完全には辿れなかった、あるいは理解できなかったもの。ギャップについては正直に書くこと。
