# 操作を冪等にする

何回動いても、どこから始まっても正しい状態へ収束するように操作を設計する。状態を変えるすべての操作は「これが 2 回動いたらどうなるか。前回の実行が途中でクラッシュしていたらどうなるか」に答えられなければならない。

**なぜ:** コマンド、ライフサイクル操作、処理ループは、クラッシュ・再起動・リトライが日常である場所で動く。部分的な状態が次回実行の結果を変えるなら、再起動のたびにデバッグ作業が発生する。

**パターン:**
- 収束する起動処理: 既存の状態をスキャンし、古いアーティファクトを掃除し、生きているセッションを引き取る
- 内容ベースの掃除: 作成順ではなく内容の等価性で比較する
- 自己修復するロック: PID ベースの stale ロック検出を使う
- 冪等なスケジューリング: 失敗した処理はきれいに再スポーンし、サイクルごとに入力を再生成する

**テスト:**
1. これが 2 回続けて動いたらどうなるか。
2. 前回の実行があらゆる箇所でクラッシュしていたらどうなるか。
3. 再実行は同じ最終状態へ収束するか。

いずれかの答えが「後に残された状態次第」なら、その操作には調停 (reconciliation) のステップが要る。
