# Laziness Protocol

最小のコードと複雑度で最大の結果を狙う。

- **削除を優先する。** リファクタや改善を求められたら、追加より先に除去を探す。
- **呼び出し階層をフラットに保つ。** 深い呼び出し連鎖を避ける。実質的な仕事を隠す豊かなインターフェイスは深い呼び出し連鎖ではない。1 つの問いに答えるのに 3 つを超えるファイルやレイヤを辿る必要があるなら、フラットにする。
- **決定を 1 箇所に集約する。** 同じ選択を複数の場所で繰り返さない。単一の信頼できる情報源の背後に置き、結果を単純なフラグとして渡す。
- **差分を最小化する。** 問題を解く最小の変更をする。少ない行数が「エレガントな」ボイラープレートに勝る。
- **引き回しを疑う。** 型、スキーマ、パイプライン、あるいは類似のレイヤを通して新しいシグナルを渡せというタスクなら、立ち止まってより直接的な経路を探す。
- **小さな漏れに汗をかく。** 小さな素通し、表現の漏れ、重複した選択は、広がる前に取り除く。小さな漏れは積み重なって恒久的な調整コストになる。

**判定基準:** 人間の開発者がそのコードの保守を消耗すると感じるなら、それは悪い解だ。
