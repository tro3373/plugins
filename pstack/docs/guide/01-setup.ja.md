# pstack をセットアップする

このページではプラグインをインストールし、pstack が使うモデルを選び、最初のタスクを走らせる。セットアップはコマンド 1 つと短い会話だけである。

## プラグインをインストールする

Cursor のチャットで次を実行する:

```text
/add-plugin pstack
```

Cursor がプラグインのインストールを確認する。

## モデルを選ぶ

次を実行する:

```text
/setup-pstack
```

[`/setup-pstack`](../../skills/setup-pstack/SKILL.md) はアクセスできるモデルを検出し、reasoning budget を尋ね、各ロール (コードの委譲先、判断、レビューのパネル) を提示し、何を使いたいかを尋ねる。質問に答えると `~/.cursor/rules/pstack-models.mdc` が書かれる。これは pstack のすべての skill が読む小さなルールである。

既定値は `xhigh` の reasoning で走る。これは `large` budget と同じである。`unlimited` は各モデルをその最上位の段階まで、最大 `max` まで引き上げる。Opus は `max` まで上がる。Grok は `xhigh` が上限なので、そこに留まる。`medium` と `small` は reasoning を下げ、使うトークンを減らす。

上書きするのは自分が気にするところだけでよい。ルールに行のないロールは skill の既定値を保つ。既定値に戻すには、そのロールの行を消す。`/setup-pstack` を再実行すると、既定値と異なるモデルを持つロールはそのまま保たれる。既定値が変わったとき、変更前に書かれたルールは古い既定値を固定したままなので、そうしたロールの行を消すか、ファイル自体を消してから `/setup-pstack` をもう一度実行する。

Auto を使ったらどうなるか気になるだろう。ロールを `inherit-parent` か `auto` にすると pstack はサブエージェントの `model` フィールドを省略し、サブエージェントは親チャットのモデルを継承する。どちらの値も同じ意味であり、いずれもモデル slug ではない。パネルのロールでは値がリストになり、エントリ 1 つにつきサブエージェント 1 体が走るので、リストの長さがパネルのサイズを決める。セットアップは `swarm workers` も設定する。これは race が各アームにモデルを指定しない限り、すべての `/swarm` ワーカーが使う既定のモデルである。

## 検証の提案を受けるか、受けないか

セットアップの最後に、`/setup-pstack` はプロジェクト内でアプリの挙動を証明する手段 (`verify-*` skill か既存のハーネス) を探す。どちらも見つからなければ、[`/create-verification-skill`](../../skills/create-verification-skill/SKILL.md) で 1 つ生成することを一度だけ提案する。

yes と答えると `.cursor/skills/verify-<app>/` が書かれる。これはユーザと同じやり方でアプリを操作する方法をエージェントに教える、プロジェクトローカルな skill である。引き渡す前に、その skill が動くことを一度証明する。no と答えればセットアップは先へ進む。`/create-verification-skill` は後からいつでも自分で実行できる。[検証して出す](./06-verify-and-ship.ja.md#プロジェクトの検証-skill-を作る) が、これを詳しく扱う。

pstack がはじめてなら yes と答えること。自分の作業を確認できるエージェントは、確認が通るまで進み続ける。確認できないエージェントは、すべての結果を手で確認させるためにあなたへ返してくる。このガイドの中で、検証 skill が最も見返りが大きい。

セットアップ後は新しいチャットを始める。モデルのルールは新しいセッションに適用される。

## コストを抑える

pstack はサブエージェントとレビューのパネルに余分なトークンを使う。それが厳密さの対価である。使う量を減らすには:

- `/setup-pstack` を再実行し、より小さな reasoning budget か安いモデルを選ぶ。メインのチャットに強いモデル、コードのロールに安くて速いモデルという分け方がよい。
- ロールを `auto` か `inherit-parent` にして、チャット自身のモデルで走らせる。
- パネルのリストを短くする。エントリ 1 つにつきサブエージェント 1 体が走る。
- `/poteto-mode` は厳密さが要る作業のために取っておく。小さく自明な編集には要らない。

## 最初のタスクを走らせる

現実的だが小さいものを選び、同僚に説明するのと同じやり方で書く:

```text
/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.
```

todo リストを見る。最初の項目群はマッチしたプレイブックのステップがコピーされたもので、このプロンプトなら Feature プレイブックである。`/poteto-mode` がステップを飛ばした場合、そのステップは `skip: <reason>` 付きでリストに残るので、何をやらないと判断したのかが見える。

ここから先は普通にフォローアップを打てばよい。チャット全体で `/poteto-mode` を有効に保つには、`/` メニューから Enter の代わりに Option+Enter (Mac) か Alt+Enter (Windows) で選ぶ。そうすると [Custom Mode](https://cursor.com/docs/skills) になり、抜けるまで毎ターンコンテキストに残り続ける。Custom Mode は Agents Window と CLI で使える。素の Enter では skill は 1 つのメッセージにだけ付き、チャットが進むにつれて薄れていく。
